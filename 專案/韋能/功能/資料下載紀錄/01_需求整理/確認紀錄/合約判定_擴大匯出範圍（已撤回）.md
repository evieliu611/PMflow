# 合約判定（已撤回）：空間分析報告匯出紀錄納入 Excel、KML 與競合分析 Excel（F-06、F-07）
> 日期：2026-11-05｜提出者：PM｜判定：⚠️ 模糊，偏超出（原判定）｜**狀態：已撤回【客戶確認 2026-11-13】**，客戶決定只記錄空間分析的 PDF，維持合約 3.2 範圍，不追加報價；本檔由 06_變更紀錄 移至確認紀錄

## 需求原文
目前空間分析報告匯出紀錄只記 PDF。前台空間分析其實還有 Excel、KML 匯出，競合分析也有 Excel 匯出，這些都要納入後台的匯出紀錄。空間分析可一次多選匯出，2 個以上會自動壓縮，後台介面要有合適的呈現。希望另做一份雛型（不取代既有的）來看介面、跟技術討論可行性；若開發工作量差異不大，可以直接幫客戶做。

## 合約判定
- 依據：增補協議項次 3.1/3.2「後台使用記錄：…資料下載紀錄（帳號、下載時間、下載 PDF）」，3.1/3.2 合計 NT$110,000（見 memory/合約範圍_增補協議）。
- 3.2 字面只有「下載 PDF」。Excel（空間分析分析清單、競合分析資料）、KML（空間分析查詢範圍）的匯出紀錄，字面不在 3.2 內；這些檔案的產出分屬 2.4（競合分析，④點資料匯出表格）、2.6（kml 上傳／下載）與既有空間分析「匯出資料」，紀錄本身未寫進任何一項。
- 判為 ⚠️ 模糊，偏超出：若客戶解讀「資料下載紀錄」涵蓋所有匯出，可能算範圍內；否則屬擴充。交主管確認立場，**不要自行裁定在範圍內**。
- 依據出處僅憑專案記憶與增補協議摘要；原合約條文請主管對照確認。

## 影響範圍
- 清單新增兩欄「功能」「匯出檔案」與兩個篩選條件（查詢條件順序與清單一致、寬度不夠整組換行）；欄位順序為項次、帳號、姓名、匯出時間、功能、匯出檔案；一次匯出一列，沒有「操作」欄，匯出檔案欄每個檔案一顆按鈕（顯示類型 Excel／PDF／KML），含 2 個以上檔案多一顆 ZIP 按鈕（Excel、PDF、KML、ZIP 各有固定位置，沒有的位置顯示淡色「—」）（見 [雛型 v2](../02_雛型/雛型_v2_後台_資料匯出紀錄.html)，v1 保留不動）。
- 後端：前台各匯出入口（空間分析、競合分析，之後的 2.5「匯出報告」）成功匯出時要回報「功能＋檔案清單」；Excel、KML、競合分析 Excel 也要留存；ZIP 按鈕於後台點擊當下才壓縮（PM 轉述：各檔案於前台產出時已先儲存）。
- 規格 v1 受影響章節：§一 概述與 User Story、§二 畫面清單、§三 3.2 欄位表（新增功能、匯出檔案欄，欄位順序調整）與查詢條件、業務規則（BR-02 紀錄範圍、BR-03、BR-04，新增匯出檔案按鈕與 ZIP 按鈕規則）、§五 非功能（儲存空間）、AC（F-05 紀錄範圍 AC-11、35～37 需改寫，新增多檔、ZIP 按鈕、篩選、競合分析等 AC）、追溯表與附錄 B。**待 v2 定案後再跑 `/spec-gen` 升為規格 v2，不直接改規格 v1**。
- 設計交付與 Design 畫布：v2 定案後才同步，v1 維持現狀。

## 建議應對
1. 先與主管確認立場（Q-07），再決定是否向客戶說明。
2. 帶雛型 v2 找技術主管，確認 Q-08～Q-10（壓縮時機與逾時、各入口回報檔案清單、儲存空間）並評估開發工作量差異（Q-12）。
3. 若工作量差異不大且主管同意：納入並向客戶說明；若判為範圍外：追加報價，或本期維持 v1（只記 PDF），其餘列下期。
4. 結論回來跑 `/req-intake`（模式 B）回填雛型，再 `/spec-gen` 產規格 v2。
