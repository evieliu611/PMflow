# /interview-deck — 需求訪談簡報

承接 `/req-intake`：雛型與需求摘要已有，現在要把它變成「能在客戶面前操作、能當場收答案」的簡報。
**簡報不是新的需求來源**：內容全部從 `01_需求整理/`、`02_雛型/` 抽取，簡報與雛型不一致時以雛型為準，回頭改簡報。

## 輸入與輸出

| 項目 | 位置 |
|---|---|
| 讀 | `01_需求整理/01_需求摘要.md`（Q-表）、`資料介接檢核_*.md`、`02_雛型/` 最新版雛型、專案 `memory/`（先讀 MEMORY.md） |
| 寫 | `02_雛型/{YYYYMMDD}_{案名}_需求訪談.html`、同名 `.pdf` |
| 命名 | PM 指定時照 PM 的；沒指定時用 `{日期}_{專案簡稱}_需求訪談`，**HTML 與 PDF 同名**。改名要同步 `<title>`、`index.html`、專案 memory 裡的引用 |

## 版型

**外殼用參考實作複製，不要重寫**：`專案/NCDR健康豬/功能/養豬場決策儀表板/02_雛型/20261119_NCDR養豬場平台_需求訪談.html`（連同 `assets/`）。
只改檔案開頭 `RAW` 陣列（內容）與 `PROTO` 常數（雛型檔名）。要換公司風格，換 `assets/` 的背景圖與 Logo、改 CSS 變數。

- 舞台固定 1600×900，用 `translate(-50%,-50%) scale(k)` 縮放置中；**必須在 1366×800 筆電也不被切掉**（用絕對定位置中，不要 grid 置中超大箱子）。
- 風格以客戶／公司母片為準（NCDR 案＝瑞竣藍綠母片）。母片是 pptx 時，從檔內抽背景圖與 Logo 放 `assets/`。

### 頁面種類（`kind`）

| kind | 用途 |
|---|---|
| cover | 封面：標題、小標、「公司 窗口姓名」 |
| table / cols5 / cmp | 資料來源清單、各來源欄位（多欄並排）、兩來源比較 |
| proto | **內嵌雛型 iframe ＋ 右側說明框**，雛型上放編號標註，與說明框雙向連動 |
| fq / qlist / todo / summary | 待確認問題、清單；內容太長會自動分頁 |
| text | 一般文字頁 |

### 內建互動（要保留）

- 雛型放大縮小／重設／全螢幕；放大後工具列縮成右上角小圖示，滑鼠移過去才展開，**不可蓋住雛型內容**。
- 雛型上的編號標記 ↔ 右側說明框連動：點標記只剩對應說明框，可回復。
- 說明框內容多時**自動分頁**（依面板高度量測），不讓內容被切掉。
- 切頁器（G）、頁碼點點列、← →、**滑鼠滾輪翻頁**（說明框可捲動時不攔截）、F 全螢幕、N 講者備註。
- 簡報嵌入雛型時網址加 `deck=1`，雛型要隱藏「討論模式」按鈕。

## 內容順序（NCDR 案驗證過）

1. 封面
2. 資料來源與本期範圍（全部來源清單，標「有資料／規劃中」）
3. 資料來源確認（各來源欄位並排，先讓客戶確認「拿得到什麼」）
4. 目前規劃：整體畫面 → 各功能畫面（每頁一個雛型情境，右側為「**規劃說明**」，不再提問）
5. 細部資料確認：只放客戶才答得出的題目
6. 最後一頁：資料與相關呈現確認（更新頻率、樣本、嵌入方式）

## 內容規則

- **先判合約範圍**：只放合約內、且 1020 之類介接欄位表有列的資料。超出合約的要求（如向對方要欄位清單外的資料）**不出現在簡報**。
- **決策者分流**：「跟既有系統一致」「我方可自行決定」「技術／畜牧司才答得出」的題目不放；`技術` 題另行口頭處理。放進簡報的題目要能請承辦當場回答。
- **題目不加內部編號**（Q-xx、T-x）、不加「待確認」標註、不加副標說明；寫成一句話的問句。
- 說明框「現況」寫雛型實際行為，不能與雛型不一致（欄位名、順序、數字都以雛型為準）。
- 標註座標 `at:[x,y]` 以雛型 1500×860 畫面為基準；雛型改版後要重新核對標記是否仍指在對的元件上。
- 用語：台灣用語；「坐標」不是「座標」；公司窗口署名用「瑞竣科技　姓名」。
- 簡報裡的題目與討論文件／Q-表不必一對一，但**不能互相矛盾**；題目增刪後回寫 `01_需求摘要.md` 的 Q-表。

## 流程

1. 讀 memory、需求摘要、雛型最新版；確認雛型已是要給客戶看的版本（若未對外過可原地改，已對外過要升版，見 CLAUDE.md 雛型版本規則）。
2. 複製參考實作與 `assets/`，改名、改 `PROTO`、重寫 `RAW`。
3. 逐頁用 headless Chrome 截圖檢查（見環境踩雷）：1600×900 與 1366×800 各看一次，確認沒切掉、標記位置正確、分頁正常。
4. **PM 看過、說「OK」再往下**：不要自己決定匯出 PDF 或發布。
5. 匯出 PDF（見下）。
6. 發布 Artifact（見下），回報連結。

## 匯出 PDF

```bash
python .claude/skills/interview-deck/scripts/export_pdf.py "<簡報.html>" "<輸出.pdf>" "<暫存資料夾>"
```

- 每個畫面一頁；說明框分頁的每個分頁各輸出一頁（所以 PDF 頁數會多於簡報頁數）；底部換頁工具列會隱藏。
- 雛型畫面是匯出當下的狀態；簡報或雛型再改，要重新匯出。

## 發布成 Artifact

1. 先呼叫 Artifact `quickstart`（intent=other），再發布。
2. 單檔 HTML 帶外部資源，不能直接當頁面：用 `files` 把簡報（`deck.html`）、雛型（`proto_v3.html`）、`shared.css`、`assets/*` 一起傳；頁面本身是一個極簡 `index.html`（`<title>` ＋ 滿版 `<iframe src="deck.html">`，顏色用 token、body 設背景）。
3. 發布用的檔名要改：**路徑不可以底線開頭**（`_shared.css` → `shared.css`，雛型內的 `<link>` 同步改）、中文檔名改 ASCII（簡報內 `PROTO` 指向改成 `./proto_v3.html`）。在暫存資料夾改，不動專案原檔。
4. 更新時用同一個檔案路徑重新發布；改名字只要改 `<title>` 與 iframe 的 `title`。
5. 發布後如實告知分享狀態（預設私人；工具回報若是組織內共享要提醒 PM）。雛型也要另外發成獨立 Artifact 時，重複上述步驟（頁面 iframe 指向 `proto_v3.html?frame=0`）。

## 環境踩雷

- headless 截圖：**完整絕對路徑**；帶查詢字串要用 `file:///` ＋ URL-encode 的路徑；要加 `--virtual-time-budget`；CSS transition 在截圖時不會跑完，驗證放大等狀態時先關 transition。
- 簡報的 `#pN` 換頁只能是純 `#pN`；匯出要傳說明框分頁用 `?q=K` 查詢字串，不要塞進 hash。
- Python 用完整路徑呼叫（Git Bash 下 `python` 可能沒輸出）；含中文的輸出寫檔再讀，避免終端機亂碼。
- 此工作區沒有版控：覆蓋前先備份到 scratchpad。
