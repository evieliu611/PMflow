# _共用素材 — 跨功能共用的原始素材

同一批素材（合約、訪談簡報、系統截圖）常被多個功能用到，所以放在專案層級、**放一次就好**，不要在每個功能資料夾各放一份。

## 子資料夾放什麼

| 子資料夾 | 放什麼 |
|----------|--------|
| `合約/` | 合約、需求說明書、服務建議書、投標須知、SOW |
| `現有系統截圖/` | 客戶目前系統的畫面截圖（PNG/JPG） |
| `往來email/` | email 匯出檔（.txt/.eml/.msg）或需求相關往來紀錄 |
| `需求摘要/` | 需求書、評選／訪談簡報、規格草稿、PM 自己整理的需求筆記 |
| `會議記錄/` | 會議簡報、會議紀錄、錄音摘要 |
| `既有成果/` | **專案級長期文件**：專案知識庫、系統架構與維運 SOP、成果報告書、期中期末報告、教育訓練手冊 |
| `轉檔MD/` | Office/PDF 經 markitdown 轉出的 .md（原檔仍留在各分類夾） |
| `其他/` | 判不出類型的，待 PM 認領 |

**`既有成果/` 跟其他分類的差別**：它收的不是「某次收到的素材」，而是**已完成、會長期被引用的專案級文件**。判準：這份東西是在描述「系統或專案整體長什麼樣」，而不是「某個功能要做什麼」。

## 不要自己分類（建議做法）

新素材全部丟進 `../未處理素材/`，然後執行：

```
/material-intake 專案/{專案名}
```

AI 會逐檔讀懂內容、分類歸檔到這裡並改成好認的檔名，同時把每份素材的重點摘要寫進專案 `memory/` —— 之後其他 skill 靠 Memory 與摘要就夠，不必每次重讀原始檔，省 token 也省時間。

## 讀取原則（省 token）

- **優先讀 `轉檔MD/` 的 .md**，要看畫面才開原檔。轉出的 MD 不含圖片內容。
- 素材清單、每份素材的定位與關鍵事實看專案的 `memory/素材清冊.md`，不要重掃目錄樹。
- 持續更新的會議紀錄彙整檔（檔名帶「至 {日期}」）：新版當新檔入庫、**舊版保留**（舊版是當時的證據），回填時只讀新增段落。

## 下一步

素材備齊後，針對某個功能執行：

```
/req-intake 專案/{專案名}/_共用素材 --功能 {功能名}
```

口述或臨時補充的需求，在對話中直接說即可。產出會寫入 `../功能/{功能名}/01_需求整理/` 與 `02_雛型/`。
