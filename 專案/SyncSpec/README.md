# {專案名} — 專案資料夾

> 複製本 `_範本專案` 資料夾並改名為實際專案名，即可開始。
> 結構 by 功能切分：素材共用、每個功能各自跑 需求 → 雛型 → 規格。

## 資料夾結構

```
{專案名}/
├── 未處理素材/            ← 收件匣：新素材先丟這裡，跑 /material-intake 自動分類歸檔
├── memory/                ← 本專案的 AI 記憶（素材清冊、關鍵事實），隨專案資料夾交接
├── _共用素材/             ← 跨功能共用，PM 放一次即可
│   ├── 合約/  現有系統截圖/  往來email/  需求摘要/  會議記錄/
│   ├── 既有成果/          ← 專案知識庫、系統架構與維運 SOP、成果報告書、期中期末報告
│   ├── 轉檔MD/            ← Office/PDF 轉出的 .md（AI 讀這個比讀原檔省 token）
│   └── 其他/
└── 功能/
    └── {功能名}/          ← 複製 _功能範本 改名；每個功能一個資料夾
        ├── 01_需求整理/   需求摘要（精簡）、參考截圖/、確認紀錄/     — /req-intake 產出
        ├── 02_雛型/       雛型各版 HTML、唯一一份 _shared.css、
        │                  畫面截圖/、訪談重點.md、index.html        — /req-intake 產出
        ├── 03_規格文件/   需求規格（含可勾選 AC）、畫面截圖/         — /spec-gen 產出
        ├── 04_設計稿/     00_設計交付.html、圖/、設計稿檔            — /spec-gen 產出交付頁
        ├── 05_驗收/       驗收「結果」（標準在規格 §六，不另產清單）
        └── 06_變更紀錄/   只放「超出合約範圍」的商業變更
```

`01_需求整理/` 是可以**整包交出去給 PL 或設計參考**的脈絡包：需求摘要 ＋ 素材截圖 ＋ 雛型畫面截圖 ＋ 每一次確認紀錄。

## 標準操作動線

PM 主線只有三支 skill。`/req-intake` 是主力，一個功能會跑很多次。

```
0. 新素材丟進 未處理素材/，跑 /material-intake 專案/{專案名}
   → 自動分類歸檔到 _共用素材/，重點摘要寫進 memory/
        ↓
1. /req-intake 專案/{專案名}/_共用素材 --功能 {功能名}
   → 逐輪選擇題收斂需求 → 01_需求整理/01_需求摘要.md + 02_雛型/雛型_v1_*.html
   ↺ 看畫面覺得不對就重跑（原地改），反覆收斂直到對了
        ↓ 帶雛型找技術主管口頭談可行性 → 結論重跑一次 req-intake 回填
2. /req-intake 專案/{專案名}/功能/{功能名} --訪談準備
   → AI 先把「PM 自己能決定」的題目當場問掉，只把要客戶拍板的寫進 02_雛型/訪談重點.md
        ↓ 客戶訪談（截圖用 02_雛型/畫面截圖/）
3. /req-intake 專案/{專案名}/功能/{功能名} --回饋 <會議記錄路徑>
   → 回饋逐條歸戶回填雛型（對外看過的版本凍結，改進 雛型_v2_*.html）
     ＋ 01_需求整理/確認紀錄/
   ↺ 還有沒問到的 → 再排訪談，回步驟 2
        ↓
4. /spec-gen 專案/{專案名}/功能/{功能名}/02_雛型
   → 03_規格文件/（需求規格＋可勾選 AC）＋ 04_設計稿/00_設計交付.html
     PM 審閱、主管確認技術規則後定稿
        ↓
5. 交付技術團隊：規格給 PG（AC 表就是自測清單）、設計交付頁給設計
   開發任務拆解／API／DDL 由技術團隊自行處理，不在 PM 主線
```

**客戶改需求（任何時候）**：跑 `/req-intake 專案/{專案名}/功能/{功能名}` 並說明客戶要改什麼。
→ AI 先比對合約判定範圍（✅合約內／⚠️模糊先問主管／❌超出**需追加報價，先別答應客戶**），再從雛型改起，並列出規格哪幾章要跟著改。改完跑 `/spec-gen` 同步，**不要手動改規格**。

## 命名與版本規則

- 檔名帶版本號，**全流程一致**：雛型 v3 → 規格 v3。對不上代表有文件沒同步。
- **雛型從 v1 起算**（沒有 v0），全部住 `02_雛型/` 靠檔名分版。**不要另開 `02_雛型_v2/` 這種資料夾。**
- 升版時機一句話：**對外（客戶或主管）看過的版本就凍結，之後的修改進下一版；還沒對外過就原地改。**
- **`_shared.css` 全資料夾只有一份**，改樣式是追加。複製一份必然各自演化，風格就分岔了。
- **雛型 HTML 只住在 `02_雛型/`**，`01_需求整理/` 只放 .md 與圖。
- 需求變更一律**從 `02_雛型/` 的 HTML 改起**，再往下游推。
- **確認紀錄 vs 變更紀錄**：一般確認（訪談、主管結論、PM 決定）進 `01_需求整理/確認紀錄/`；只有超出合約需追加報價的進 `06_變更紀錄/`。
