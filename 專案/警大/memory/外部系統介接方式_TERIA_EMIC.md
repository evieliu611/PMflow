# 外部系統介接方式：EMIC 與 TERIA

## EMIC（消防署 應變管理資訊系統）
- **無歷程API**：消防署現有災情API不提供處理歷程資訊，只能拿到當下狀態快照。
- **無正式介接機制**：任務主要用於演習，目前未提供正式API介接機制；消防署將提供「演練區」災情API供本案使用。
- **查詢限制**：單次查詢筆數上限 100 筆，可用縣市、鄉鎮市區、時間點條件縮減。
- **已定案的呼叫頻率**：演練開始後**每10分鐘**呼叫一次EMIC災情API，判斷處理狀態並更新/儲存。警大防災所已接受此頻率造成的時間差或歷程缺失。
- **屬性欄位**（已定案）：案件編號、發生時間、所在縣市、鄉鎮市區、發生地點、災情類別、災情項目、災情描述、處理狀態、聯絡姓名、聯絡電話、人員受傷/死亡/受困/失蹤/收容人數、交通障礙、重大災情、結案狀態、退水狀態（僅積淹水災情有）、通報來源、案件更新時間。
- **14類災情圖徵**（已設計完成，見 [[素材清冊]] 的規劃畫面素材）：路樹、廣告招牌、道路隧道、橋梁、鐵路高鐵捷運、積淹水、土石、建物毀損、水利設施、民生基礎設施、車輛交通事故、環境汙染、火災、其他。每類配4種處理狀態色（灰=未指派、紅=待處理、黃=處理中、綠=已處理），另有無狀態色版供線上製圖模組共用。
- **篩選條件**（已定案）：災情類別（可複選）、縣市、災情狀態（可複選）。
- **API 實際規格**（【更新 2026-08-04】，見 [[素材清冊]] 的「EMIC演練區災情API與欄位說明」）：
  - Endpoint：`POST https://sportal.emic.gov.tw/DSP2_Develop/api/41wRY/QuerySS`
  - Request body：`county`（縣市，可空字串）、`startTime`／`endTime`（`yyyy-MM-ddTHH:mm:ss`）、`disaster_type`（可空字串）
  - Response 欄位與型別：`CASE_ID`(string 案件編號)、`CASE_DT`(DateTime `yyyy-MM-ddTHH:mm` 發生時間)、`COUNTY_N`/`TOWN_N`(string 縣市/鄉鎮)、`CASE_LOC`(string 發生地點)、`GEOMETRY_TYPE`(string，點/線/面)、`COORDINATE`(string，WGS84經度,緯度)、`DISASTER_MAIN_TYPE`/`DISASTER_SUB_TYPE`(string，依EMIC災情類別表)、`CASE_DESCRIPTION`(string)、`CASE_STATUS`(string：未指派/待處理/處理中/已處理)、`peopleName`/`peoplePhone`(string)、`INJURED_NO`/`DEATH_NO`/`TRAPPED_NO`/`MISSING_NO`/`SHELTER_NO`(integer 人數)、`IS_TRAFFIC`/`IS_SERIOUS`/`IS_CLOSE`/`IS_RETREAT`(string，是/否；`IS_RETREAT`退水狀態僅積淹水災情才有)、`RPT_SOURCE`(string，依EMIC通報來源類別表)、`FILE_LIST`(陣列，含`FILE_TYPE`與`FILE_URL`附件下載連結)、`MODIFIED_DT`(DateTime 案件更新時間)。
  - 此 API URL／參數屬「警大_瑞竣」雙方協議的專用介接，非公開API，**規格文件與雛型SPEC寫API串接細節時直接引用這組**，不要自己另外猜欄位。
- **需求收斂決議（【更新 2026-08-05】跑 /req-intake 模式A 產 `功能/EMIC災情/` 雛型 v1，PM evieliu 逐輪確認）**：
  - **時序資料的產生方式**：EMIC 無歷程 API，時序變化由本系統自行累積。**不逐次儲存全快照**（省空間）；每 10 分鐘取回時比對，**只有案件狀態有變更時，才在對應狀態欄位記下該變更的時間點**。時間播放器在時間點 T 的呈現＝取各案件「時間戳 ≤ T 的最後一筆狀態」，發生時間 > T 者視為「尚未發生」不顯示。
  - **點位兩個控制**：眼睛＝地圖顯示/隱藏，**開關狀態隨專案儲存**（隱藏≠刪除，資料仍在）；刪除＝二次確認後永久移除，**刪掉的災情不出現在專案、也不會被儲存**。
  - **演練日期限制**：頂部時間選擇器由「起迄兩個時間」**簡化成單一區塊、只設定到日期**，且鎖定當天。
  - **23:59 自動收尾**：當天 23:59 若使用者未按「結束演練」，系統**自動視同結束演練**（停止呼叫新災情、專案轉「演練完成」並凍結，非只停呼叫）。
  - **查詢範圍**：全國查詢、系統自動分批取完（單次上限 100 筆）。**Q-01 已於 2026-08-05 經技術主管確認銷案**：分頁機制由開發者實作；效能受 EMIC 端影響、我方較不可控；API 逾時／無回應加重試機制；重試仍失敗導致的狀態歷程缺漏，屬 EMIC API 本身限制、客戶（老師）已表示可接受。重試次數／間隔屬開發實作細節，本階段不定義。
  - **雛型版本**：v1（初次收斂，Q-01 未決，帶去給技術主管看）→ v2（2026-08-05 回填 Q-01 銷案）。
  - **規格已定稿（2026-08-05）**：`03_規格文件/01_需求規格_EMIC災情_v2.md`（對齊雛型 v2，含 F-01～F-11、14 類圖徵、BR-01～BR-14、26 條 AC）＋`04_設計稿/00_設計交付.html`（圖徵素材為主要設計交付物）。無阻擋性待定；重試次數／間隔屬開發實作細節不定義。這份規格＝交付技術團隊的唯一依據；之後變更一律回 `/req-intake` 從雛型改起。

## TERIA（國家災害防救科技中心 地震衝擊資訊平台）
- **無API開放**：NCDR目前未開放TERIA資料API介接方案，僅能下載 KML、Shapefile、CSV 檔案。
- **已決議的介接方式**：改為「使用者於系統上傳TERIA模擬結果檔案」，而非即時介接。警大防災所需填寫TERIA權限開通申請單。
- **資料範圍**：現有36條斷層模擬結果＋歷年國家防災日成果；警大已提供需納入的TERIA專案清單共19筆（後續團隊下載匯入）。
- **分頁命名**：因納入TERIA＋國家防災日兩種來源，系統圖資分頁改稱「地震情境」（不再單獨稱TERIA）。國家防災日檔案內容不一致、一年更新一次，決議由團隊整理後直接寫入資料庫，**不提供後台上架機制**。
- **級距與呈現規則**（已於20260610會議定案，見該場簡報表格）：震度3級以下不顯示；建物完全/嚴重損壞棟數分5級距（0-0.5/0.5-10/10-50/50-100/100-5000），中輕度損壞不需納入；人口死亡/重傷/中傷僅日間時段；道路橋樑通行失敗機率、供水供電不服務機率皆有固定級距（詳見簡報原檔）；供電不服務機率讀取「中度以上受損機率(FC_Mdr)」欄位而非原中度受損機率(Mdr_D)；各分析結果不分縣市呈現，原始資料若拆分需先合併。
- **3D建物上色**：完全損壞＝黑色、嚴重損壞＝紅色，同圖層展示；已驗證TERIA建物損壞網格數值可自動上色，但為效能考量會限縮呈現範圍或改採預先計算。
