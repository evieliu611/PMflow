# /material-intake — 素材分類與入庫（管線前置）

PM 拿到新素材時不必自己想放哪、取什麼名字：全部丟進 `未處理素材/`，跑這支 skill。skill 會讀懂每份檔案是什麼、分類歸檔、並把「這份素材講了什麼」寫進 Memory —— 目標是**之後任何階段 skill 需要背景時，優先靠 Memory 與素材摘要就夠，不必每次重讀原始 PDF/docx 燒 token**。

## Usage

```
/material-intake 專案/{專案名}                 # 處理該專案的 未處理素材/
/material-intake 專案/{專案名} --功能 訂單管理  # 已知這批素材屬於哪個功能時標註（可選）
```

- 收件匣位置：`專案/{專案名}/未處理素材/`（不存在時建立並提示 PM 把檔案放進來）。
- 未指定專案時，掃 `專案/` 下哪個專案的 `未處理素材/` 有檔案；多個都有就問 PM 要處理哪個。

## 資料夾約定

```
專案/{專案名}/
├── 未處理素材/          ← 收件匣：PM 只管往這裡丟，處理完應清空
├── memory/              ← 本專案的 AI 記憶（素材清冊、關鍵事實），隨專案資料夾交接
└── _共用素材/           ← 歸檔目的地，依類型分子資料夾
    ├── 合約/
    ├── 現有系統截圖/
    ├── 往來email/
    ├── 需求摘要/        ← 需求書、簡報、規格草稿
    ├── 會議記錄/
    ├── 既有成果/        ← 專案知識庫、系統架構與維運 SOP、成果報告書、期中期末報告、教育訓練手冊
    ├── 轉檔MD/          ← markitdown 轉出的 .md（原檔仍保留在各分類夾）
    └── 其他/            ← 判不出類型的，並在回報中請 PM 認領
```

**`既有成果/` 與其他分類的差別**：它收的不是「某次收到的素材」，而是**已完成、會長期被引用的專案級文件**。判準：這份東西是不是描述「系統或專案整體長什麼樣」而非「某個功能要做什麼」？是 → `既有成果/`。這夾的內容通常是 `/req-intake` 理解系統現況的重要依據，值得優先寫進 Memory。

- **原檔一律保留**，分類是「搬移＋改名」，不是轉換取代。
- 改名原則：一看就懂用途，如 `合約_農水署發電回饋金系統_2026.pdf`、`現有系統_案場清單畫面.png`。原檔名有意義的資訊（日期、版本）要保留。
- 同名衝突時加序號，不要覆蓋既有歸檔。

## What You Must Do When Invoked

### 步驟 1：盤點收件匣
1. 列出 `未處理素材/` 內所有檔案。空的就回報「收件匣是空的」並結束。
2. 讀 `專案/{專案名}/README.md` 與既有 Memory 的素材清單，掌握**已入庫**的素材，避免重複處理與重複寫 Memory。

### 步驟 2：先轉檔成可讀形式（讀取之前一律先轉，不要邊看原檔邊自己判斷要不要轉）
**鐵則：先把整批素材轉成可讀形式，再進步驟 3 讀。順序不可顛倒**——不是先讀原檔、再依自己想法挑幾份轉 MD。

1. 用 `command -v markitdown` 檢查是否已安裝。
2. **有安裝** → 問 PM 一次：「偵測到 markitdown，要不要把這批 Office/PDF 檔轉成 MD 存到 `_共用素材/轉檔MD/`？之後其他 skill 讀 MD 比讀原檔省 token。」
   - PM 同意 → **先把整批 Office/PDF 逐檔轉出**：`markitdown "{原檔}" -o "{scratchpad}/{序號}.md"`（先落 scratchpad，等步驟 3 定了分類檔名再連同原檔歸位；避免用尚未定案的名字）。
   - PM 不同意 → 不轉 MD，步驟 3 直接對原檔讀取。
3. **沒安裝** → 不提、不代裝，步驟 3 直接對原檔讀取。
4. **轉出後逐份抽查前幾行**，分流成兩類，兩類都要在進步驟 3 前處理完：
   - **文字層正常** → 這份步驟 3 讀 MD 即可。
   - **轉出空白/亂碼**（掃描型或圖片型 PDF、Big5 誤判 docx）→ MD 不可用，**改轉成「圖片」再讀**：PDF 用 `pdftoppm`（無則 PyMuPDF `fitz` / `pdf2image`）渲染每頁成 PNG 到 scratchpad；docx/pptx 依 [req-intake] 指引解 zip 取 `media/` 圖片。這類**不存 MD**（沒有可用文字層），步驟 3 用 Read 視覺讀渲染出的圖。Big5 亂碼 docx 標記轉檔失敗、以原檔為準。
5. 轉檔用的中繼檔（MD、渲染圖）一律寫 scratchpad，不要污染專案資料夾；只有確定要保留的文字層 MD 才在步驟 3 歸位到 `轉檔MD/`。

### 步驟 3：讀「轉檔後的內容」判斷分類（核心）
對每個檔案，讀的是步驟 2 轉出的產物（文字型讀 MD、圖片型讀渲染圖），不是憑副檔名或檔名猜：
1. **依讀到的內容判定類型**（合約 / 現有系統截圖 / 往來email / 需求摘要 / 會議記錄 / 既有成果 / 其他）。
2. 定好分類後，把**原檔**依約定改名移入 `_共用素材/` 對應子資料夾；該檔若有可用文字層 MD，一併把 MD 從 scratchpad 複製到 `轉檔MD/`，檔名與原檔對齊。
3. 讀的同時記下這份素材的：**一句話定位**（這是什麼、關於哪個功能）＋ **3~8 條關鍵事實**（金額、期限、欄位、系統名稱、介接方式、客戶明確要求…）。這是步驟 4 的原料。
4. 轉檔後仍讀不出內容（加密 PDF、損毀檔、渲染也失敗）→ 原檔移入 `其他/`，回報時請 PM 補救，不要臆測內容。

### 步驟 4：萃取寫入 Memory（本 skill 的存在理由）
Memory 位置：**`專案/{專案名}/memory/`**，by 專案各自一份（不是 `~/.claude/` 下的個人記憶）——記憶跟著專案資料夾走，版控與交接時自然一起帶走。格式沿用 memory 慣例：一事一檔（frontmatter 含 name/description/type）＋該資料夾內 `MEMORY.md` 一行一筆索引。

注意：專案 memory **不會自動載入**，靠 CLAUDE.md 指示各 skill 處理某專案前先讀該專案的 `memory/MEMORY.md` 再挑檔精讀。所以 description 與索引行要寫到「看一行就能判斷相不相關」。

1. **每個專案維護一份素材清冊 memory**：`memory/素材清冊.md`（type: `project`）。內容是表格：分類後路徑｜類型｜一句話定位｜關鍵事實摘要。已存在就**追加新素材列**並標 `【更新 {日期}】`，不要重生整份。
2. **跨 session 反覆會用到的硬事實才另立 memory**，例如：合約範圍與金額上限、客戶現有系統名稱與介接方式、關鍵業務規則（計算公式、法遵限制）。一件事實一個檔，type 用 `project` 或 `reference`，並以 `[[素材清冊]]` 互連。
3. **取捨標準 —— 寫進 Memory 的是「摘要與定位」，不是全文**：
   - ✅ 寫：素材在哪、講什麼、關鍵數字/約束 → 讓下游 skill 能判斷「需不需要開原檔、開哪一份」。
   - ❌ 不寫：整段合約條文、整張欄位表 —— 那些留在歸檔的原檔/轉檔 MD 裡，需要時精準去讀。
   - ❌ 不寫：單一功能單一階段才用得到的細節（那是 `01_需求整理/` 的事，交給 [req-intake]）。
4. 每個新 memory 檔在**該專案的** `memory/MEMORY.md` 加一行索引。

### 步驟 5：同步專案 README 並回報
1. 專案 `README.md` 的素材清單**直接連結**本專案的 `memory/素材清冊.md`，不要在 README 再維護一份重複的表（兩份表遲早對不上）；README 沒有素材清單區塊就補一個連結區塊。
2. 確認 `未處理素材/` 已清空。
3. 對 PM 回報：
   - 處理了 N 份素材：各自分到哪、改了什麼名
   - 是否轉了 MD（哪幾份、有沒有轉失敗以原檔為準的）
   - 寫入/更新了哪些 Memory
   - 列入 `其他/` 待認領的檔案
   - 下一步建議：素材備齊的功能可跑 `/req-intake 專案/{專案名}/_共用素材 --功能 {功能名}`
4. **入庫的是會議記錄時，額外提示回填**：會議記錄裡通常有客戶對某個功能的決定，而本 skill 不做需求分析。查一下相關功能的 `01_需求整理/確認紀錄/` 最後消化到哪個日期，回報時明確講：「這份會議記錄有 {功能名} 的內容、上次消化到 {日期}，建議跑 `/req-intake 專案/{專案名}/功能/{功能名} --回饋 {本次檔案路徑}` 回填。」
   - 外部會議紀錄常是**持續更新的彙整檔**（檔名帶「至 {日期}」）。新版一律當新檔入庫、保留舊版，不要覆蓋 —— 舊版是當時的證據。回填時 `/req-intake` 會只讀新增段落。

## 注意事項
- **這支 skill 不做需求分析**：它只負責「入庫＋建索引」。需求摘要與雛型 v0 是 [req-intake] 的事，不要越界產出。
- 帶了 `--功能` 參數時，在素材清冊 memory 與 README 中標註該素材關聯的功能，方便下游過濾。
- 路徑與檔名大量中文，Bash 操作一律用引號包路徑；搬移用 `mv`，不要複製後忘了刪。
- 重跑是安全的：只處理 `未處理素材/` 裡現存的檔案，已歸檔素材與既有 Memory 只增補不覆蓋。
